# Лабораторная работа №4. Ансамбли

## Данные и подготовка

Использован `german.csv` из задания: 1 000 строк, 20 входных признаков,
целевая переменная `Creditability` в первом столбце. Разделитель — `;`.
Пропусков нет. Класс 1 содержит 700 объектов, класс 0 — 300.
Положительный класс для всех метрик — `Creditability=1`.

Данные разделены через `train_test_split(test_size=0.2, random_state=42,
stratify=target)`: 800 объектов в train и 200 в test. В test — 140 единиц
и 60 нулей. Индексы разбиения точно совпадают с lab3. SHA256 данных
и индексов разбиения сохранены в `experiment_results.json`.

Семь количественных признаков оставлены числовыми: `Duration_of_Credit_monthly`,
`Credit_Amount`, `Instalment_per_cent`, `Duration_in_Current_address`,
`Age_years`, `No_of_Credits_at_this_Bank`, `No_of_dependents`.
Остальные 13 признаков закодированы через
`OneHotEncoder(handle_unknown="ignore", sparse_output=False)`.
После обучения кодировщика на всём train получается 61 признак.
Масштабирование не применялось: все проверенные модели используют деревья,
для которых стандартизация числовых признаков не требуется.

При кросс-валидации `ColumnTransformer` включён в `Pipeline`. Поэтому в каждом
фолде кодировщик обучается заново только на обучающей части этого фолда.
После выбора модели преобразования обучаются на всех 800 строках train и
применяются к test. Test не участвует в обучении, выборе признаков, параметров
или порога. Контрактная функция получает уже подготовленные числовые матрицы.

## Гипотезы и эксперименты

Проверены семь конфигураций. Для всех использованы одинаковые пять фолдов:
`StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` внутри train.
На каждом шаге обучается модель на 640 строках, а метрики считаются на 160.
Критерий выбора — максимальная средняя ROC-AUC по этим пяти фолдам.
Accuracy, Precision, Recall и F1 также измеряются, но не используются для выбора.

1. `random_forest_full`: Random Forest, 300 деревьев, без ограничения глубины,
   `min_samples_leaf=1`. Проверяется обычный bagging деревьев со случайным
   подмножеством признаков.
2. `random_forest_regularized`: 300 деревьев, `max_depth=8`,
   `min_samples_leaf=3`. Гипотеза: ограничение сложности деревьев может
   улучшить обобщение на небольшой выборке.
3. `extra_trees_full`: Extra Trees, 300 деревьев, `min_samples_leaf=1`.
   Проверяется дополнительная случайность в выборе порогов разбиений.
4. `extra_trees_regularized`: Extra Trees, 300 деревьев,
   `min_samples_leaf=3`. Проверяется влияние более крупных листьев.
5. `gradient_boosting`: Gradient Boosting, 200 деревьев глубины 2,
   `learning_rate=0.05`. Проверяется последовательное исправление ошибок
   неглубокими деревьями.
6. `hist_gradient_boosting_7`: HistGradientBoosting, 200 итераций,
   `learning_rate=0.05`, `max_leaf_nodes=7`, `l2_regularization=1`.
7. `hist_gradient_boosting_15`: те же параметры, но `max_leaf_nodes=15`.
   Последняя пара проверяет увеличение сложности базовых деревьев.

У HistGradientBoosting отключён `early_stopping`, чтобы число итераций было
фиксированным. Во всех моделях `random_state=42`. У лесов `n_jobs=1`,
у `cross_validate` также `n_jobs=1`. Другие параметры — стандартные параметры
соответствующих классов в зафиксированной версии scikit-learn.

Сначала выполнена только кросс-валидация через `--cv-only`. Её победитель
зафиксирован в `SELECTED_MODEL` до вычисления тестовых метрик.
После этого обучена финальная модель на всём train и оценена на test.
Новых конфигураций после просмотра test не добавлялось. Порог классов
не подбирался, используется стандартное предсказание выбранного классификатора.

## Выбранная модель

Выбран `RandomForestClassifier(n_estimators=300, max_depth=8,
min_samples_leaf=3, random_state=42, n_jobs=1)`.
Он имеет максимальную среднюю validation ROC-AUC: 0.7798735119047618.
Выбор не основан на тестовых метриках.

В стандартных настройках Random Forest использует bootstrap-выборки для
обучения деревьев и `max_features="sqrt"` для случайного выбора признаков
при поиске разбиения. Вероятность класса ансамбля получается усреднением
вероятностей деревьев. Максимальная глубина 8 и минимум 3 объекта в листе
ограничивают сложность каждого дерева. Контрактная функция возвращает
читаемое представление модели, вероятности класса 1, предсказанные метки
и все пять тестовых метрик.

## Выводы и ограничения

Ограниченный Random Forest показал немного большую среднюю CV ROC-AUC,
чем неограниченный: 0.779874 против 0.773996. При этом его средние Accuracy
и F1 ниже, а Recall выше. Следовательно, регуляризация не улучшила все
метрики одновременно. Разница ROC-AUC мала относительно разброса по фолдам,
поэтому статистически значимое преимущество не заявляется.

У Extra Trees увеличение минимального листа улучшило среднюю CV ROC-AUC
с 0.762965 до 0.769940. Проверенные варианты бустинга не превзошли выбранный
Random Forest по критерию выбора. Увеличение числа листьев HistGradientBoosting
с 7 до 15 немного снизило ROC-AUC с 0.763988 до 0.762500. По этим опытам
нельзя делать вывод, что бустинг в целом хуже лесов: проверена только небольшая
фиксированная сетка параметров.

На test ансамбль не превзошёл собственную логистическую модель lab3 по ROC-AUC,
Accuracy или Precision. Его Recall выше почти на 0.10, но ложноположительных
ответов больше: 43 против 24 в lab3. Всегда предсказывать 1 на этом test
дало бы Accuracy=0.70, поэтому Accuracy=0.77 нужно рассматривать вместе с
другими метриками и дисбалансом классов. F1 двух моделей близка.

Тестовая ROC-AUC 0.834881 выше средней CV ROC-AUC 0.779874. Такое различие
на малой выборке не доказывает ни улучшение метода, ни ошибку CV: обучающие
объёмы и проверочные строки различаются. Один test из 200 объектов не позволяет
надёжно оценить работу на другом распределении. Повторная внешняя проверка
и доверительные интервалы в этой работе не выполнялись.

## Воспроизводимость

Python 3.12.13, версии NumPy, Pandas и scikit-learn зафиксированы
в `requirements.txt`. Исходный CSV включён в репозиторий.
Из каталога работы:

```sh
python -m pip install -r requirements.txt
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python run_experiments.py
python -m unittest -v test_ensemble_models.py
```

Для запуска только подбора без оценки на test:

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python run_experiments.py --cv-only
```

Обычный запуск выполняет 35 обучений внутри CV и одно финальное обучение,
проверяет соответствие победителя зафиксированному `SELECTED_MODEL` и
перезаписывает `experiment_results.json` измеренными значениями. Сохранены
параметры, фолды, средние, стандартные отклонения и итоговые тестовые метрики.
Два полных запуска дали побайтово одинаковый JSON.

Семь локальных тестов проверяют диапазон и форму выходов, воспроизводимость,
независимость предсказаний от `test_target`, работу с числовым DataFrame,
обработку неизвестной категории без обучения на test и совпадение метрик
с отдельным расчётом. ROC-AUC в независимой проверке вычисляется попарным
сравнением вероятностей положительных и отрицательных объектов с учётом связок.
